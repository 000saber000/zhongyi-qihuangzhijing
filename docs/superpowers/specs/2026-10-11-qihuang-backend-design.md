# 岐黄知境：账号与云端学习记录设计

日期：2026-10-11

## 已确认的目标

在已发布的岐黄知境网页上新增用户名与密码登录、收藏与学习进度云端同步，以及首次登录时由用户选择导入本地记录。游客仍可使用网站；保留现有星海、知识库、课程与书斋的视觉风格。使用 Node.js 和 PostgreSQL，在 Render 部署。

成功标准：用户在浏览器 A 注册、收藏知识并完成课程后，在浏览器 B 登录同一账号能够看到相同记录；不同账号相互隔离；拒绝导入不改变云端或游客记录。

## 部署架构

继续使用现有 Render 静态站点和访问地址。新增一个 Node.js API Web Service，以及与 API 同区域、同工作区的 PostgreSQL；API 使用数据库内部连接地址。工作区沿用用户已确认的 `My Workspace`（`tea-d8ru33cvikkc7390ob60`）。

前端通过构建变量 `VITE_API_BASE_URL` 访问 API。API 仅允许已配置的前端 Origin；开发环境允许明确配置的本地 Origin，不使用通配符。前端启动不依赖 API 成功连接，游客可在后端不可用时继续浏览和保存本地记录。

选择独立 API 可以保留线上地址，并分别部署前端与后端。单个 Node 服务同时托管前端可以简化同源访问，但需要更换或迁移现有静态站点；本期采用前者。

实现准备好后才能创建云资源。优先使用免费计划；在实际创建前核查免费数据库的有效期与限制，并告知用户。未经用户明确授权不创建付费实例；若免费计划不可用，则完成代码与部署配置，说明需用户处理的套餐选择。

## 登录与安全

- 用户名：3–32 个 ASCII 字符，只允许字母、数字、下划线；不区分大小写，保留首次注册的显示大小写。
- 密码：10–128 个字符，不裁剪空格。使用 Node.js `crypto.scrypt` 和随机盐生成密码摘要，保存算法参数；禁止明文保存、日志输出或返回密码。
- 注册自动登录；用户名重复返回明确提示。登录用户名不存在或密码错误均返回相同的凭据错误。
- 会话使用 32 字节随机 opaque token，数据库仅存 SHA-256 摘要，有效期 7 天。退出立即撤销当前会话；过期会话返回 401。
- 前端将 token 保存在当前标签页的 sessionStorage，并通过 `Authorization: Bearer ...` 发送。刷新恢复登录；关闭标签页后通常需重新登录。账号 token 不写入 localStorage，服务端不依赖跨站 Cookie。
- 注册和登录按客户端 IP 限速，单个地址 15 分钟内最多 20 次请求；正确配置 Render 的反向代理信任边界，不信任任意用户提供的转发头。
- API 限制 JSON 请求体为 64 KB；所有输入必须验证；SQL 使用参数绑定；错误响应与日志不得泄露连接串、token、密码或内部堆栈。
- 身份从有效会话取得；接口不接受客户端指定的用户 ID。前端渲染用户输入时不使用 HTML 注入。

## 数据结构

- `users`：UUID 主键、规范化用户名（唯一）、显示用户名、密码摘要与参数、创建时间。
- `sessions`：token 摘要主键、用户外键、过期时间、创建时间；用户删除时级联删除。
- `bookmarks`：用户外键、知识 ID、创建时间；主键为用户 ID 与知识 ID。
- `lesson_completions`：用户外键、单元 ID、完成时间；主键为用户 ID 与单元 ID。

知识 ID 必须存在于当前知识 JSON。单元 ID 沿用 `${course.id}-${index}`，index 从 0 开始，必须存在于当前课程。服务端使用同一份目录生成允许的 ID 集合；拒绝未知 ID，避免存入无法展示的数据。

迁移脚本版本化、事务执行、可重复启动；不在启动时清空表。收藏与完成操作采用按条目的幂等写入，禁止使用完整数组覆盖其他设备的更新。

## API 契约

统一错误格式为 `{error: {code, message}}`。受保护接口要求 Bearer token。

| 方法与路径 | 输入 | 成功响应 |
| --- | --- | --- |
| `GET /healthz` | 无 | 数据库可用时 200 `{status: "ok"}`，不可用时 503 |
| `POST /api/auth/register` | `{username, password}` | 201 `{user: {id, username}, token, expiresAt}` |
| `POST /api/auth/login` | `{username, password}` | 200，同注册响应结构 |
| `GET /api/auth/me` | 会话 | 200 `{user: {id, username}, expiresAt}` |
| `POST /api/auth/logout` | 会话 | 204；已过期的本地会话仍可清除 |
| `GET /api/study` | 会话 | 200 `{bookmarks: string[], completed: string[]}` |
| `PUT /api/bookmarks/:knowledgeId` | 会话 | 204，重复写入不增加记录 |
| `DELETE /api/bookmarks/:knowledgeId` | 会话 | 204，不存在的收藏也成功 |
| `PUT /api/completions/:lessonId` | 会话 | 204，重复完成不增加记录 |
| `POST /api/study/import` | `{bookmarks: string[], completed: string[]}` | 200，返回合并后的学习记录 |

非法输入返回 400；错误凭据或失效会话返回 401；重复用户名返回 409；限速返回 429；数据库不可用返回 503。导入每个数组最多 500 项，去重后验证全部 ID，任何一项非法则整个导入失败；合法导入使用事务与现有记录取并集。

## 前端与同步流程

1. 未登录时沿用现有 localStorage 记录及读写逻辑。在书斋加入登录入口和账户弹窗，保留现有导航与页面布局。
2. 注册或登录成功后加载云端记录；切换账号时先清空旧账号的内存记录再加载新账号，迟到的网络响应不得进入新账号状态。
3. 若本浏览器有游客记录且未对当前账号完成过导入选择，展示“导入本地学习记录”及预览数量，由用户选择“导入”或“暂不导入”。不自动把游客记录归属到账号。成功导入后记录该账号在本浏览器的导入标记；失败不记录标记、不清除游客数据。
4. 登录后的增删操作调用对应条目接口，成功后再显示变更。请求未完成时禁用该条目的重复操作；失败显示“保存失败，请重试”，不显示“已同步”。不将登录账号的记录覆盖到游客 localStorage 键。
5. 登录后首次加载、标签页重新获得焦点以及页面可见时每 30 秒刷新云端记录。请求必须与已登录账号对应；写入过程中避免旧的读取结果覆盖写入后的状态。
6. 明确区分“保存在当前浏览器”“已同步到云端”“同步失败”。加载失败不显示空收藏作为成功状态；保留当前账号已加载记录，并允许重试。
7. 会话过期清除 token 与账户状态，提示重新登录；退出清除账号内存与 token，恢复游客记录。两个账号间不残留收藏或课程状态。

为避免数据误归属，登录或退出时舍弃旧账号尚未完成的 UI 操作；网络请求即使不能及时取消，其返回值也必须通过会话身份检查。导入暂缓不反复在同一会话中弹窗；用户可从书斋再次打开导入入口。

## 模块边界

- 前端 `src/features/account/`：账户表单、弹窗、会话状态和账户展示。
- 前端 `src/features/study/`：游客记录适配、云端读写、本地导入和同步状态；对 App 提供统一的收藏与完成操作。
- 前端 `src/lib/api.ts`：API 地址、请求头、错误解析和超时处理。
- 服务端 `server/`：独立 Node.js / TypeScript 包；分离配置、数据库连接与迁移、密码与会话、身份接口、学习记录接口及服务入口。
- 共用现有知识与课程 ID，服务端校验与前端展示依赖同一目录。
- `render.yaml`：记录静态站点、新 API 和数据库配置；API 密钥和数据库连接通过 Render 环境变量注入，不提交到 GitHub。
