# 典籍管理设计

用户希望自己在网页中添加、修改中医典籍，保存后发布到知识库。

## 范围

复用现有用户名、密码和 PostgreSQL。新增“典籍管理”页面，管理员可新增典籍、编辑现有典籍、保存草稿、预览和发布。编辑字段包括标题、副标题、简介、原文或正文、出处、标签、关联知识与学习要点。正文为纯文本，保留换行；本期不含文件上传、章节树、删除及管理其他知识类别。

## 数据与权限

版本化迁移将现有知识条目和导读存入 knowledge_entries，保留编号、已有账号和收藏。每条内容分别保存草稿和发布快照。保存草稿不影响公开阅读，发布以事务更新快照。所有写入必须验证管理员权限及版本号；过时编辑返回 409，不覆盖新内容。

复用最新账号管理功能的 users.role，普通账号为 user，管理员为 admin；公开注册不能指定角色。复用 INITIAL_ADMIN_USERNAME 指定已有账号进行启动配置，每次请求重新检查数据库权限和强制修改密码状态。典籍入口为 /#classics，原有 /#admin 保持账号管理。登录到期时保留当前编辑器输入，禁用保存，并在同页提供重新登录。不同账号切换时清除上一账号编辑状态。

## 公开内容

GET /api/knowledge 无须登录，仅返回发布快照。知识库、搜索、星海、关联、导读和正文使用同一目录。API 冷启动或不可用时保留内置内容并显示重试提示；请求成功后替换为云端发布内容。发布后当前浏览器立即刷新，其他浏览器刷新、重新聚焦或一分钟轮询可更新。收藏及导入验证使用数据库发布目录。

## 验证

用独立 PostgreSQL 数据库验证迁移幂等、权限隔离、草稿不可见、发布、保存冲突、关系验证及新内容收藏。浏览器验证管理员新增/预览/发布/阅读、普通用户受限、保存失败保留输入、移动端布局、原有账号及星海功能。生成供现有 Render 构建使用的 qihuang-unified.html。用户已指定管理员 aidejiasinuo；上线沿用现有 main 自动发布流程，Render 内部连接启动迁移和已有管理员配置。
